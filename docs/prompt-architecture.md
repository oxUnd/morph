# Prompt 组装架构

Morph 按各自独立管理的来源组装模型输入：

```text
系统指令
  核心要求（含语言与偏好优先级，始终保留）
  默认行为 + 精简的 Markdown 格式约定
    （配置为自定义 prompt 替换模式时省略）
  自定义 prompt 文件，然后是按文件名排序的目录片段
  完整的可用技能目录（启用的技能名称与描述，按名称排序）
  已启用且已激活的技能正文（按名称排序）
  运行时限制（当前最大工具调用迭代次数，始终保留）
  当前生效的记忆偏好与参考事实
  Hook 提供的上下文

仅用于当前请求的上下文
  system: 环境快照
  user:   带作用域的项目指导快照（如有）

会话消息
  assistant: 标明为历史参考的续接摘要（发生压缩时）
  之前的 user / assistant / tool 消息
  当前用户请求及后续工具交互

工具定义
  当前可用工具的函数描述和 schema，独立传入
```

Chat Completions 将系统指令作为 system 消息接收；Responses 则通过
`instructions` 字段接收。旧版纯文本后端不支持带角色的消息，因此会将仅用于当前请求的上下文追加到系统指令字符串中。

## 指令权限与任务连续性

自定义 prompt 的替换模式始终保留核心要求，包括在开始任务前检查可用技能、
对用户点名或任务匹配的技能调用 `activate_skill` 的要求（工具启用时）。技能和项目文件不能扩大权限，也不能覆盖核心要求。
核心要求还包括任务连续性与压缩后续接、以实际函数接口为准使用工具、基于证据验证结果、
根据失败证据调整行动，以及提供符合用户指定格式和前端支持格式的实际产物引用。
语言选择遵循当前明确指令、生效的保存偏好、配置默认值的顺序；均无指定时跟随当前请求语言。
保存偏好的成功声明必须有已提交结果。上述约束在主代理和子代理的 replace 模式下均保留。
角色人设、语气、规划与委派策略，以及 Markdown 等具体格式默认值仍允许替换。
最大迭代次数使用当前执行上下文独立注入，不依赖默认行为提示词，也不替代运行时的强制上限。

当前用户请求优先于技能和项目指导中的默认行为；更具体的项目指导只适用于其所在目录及子目录。
记忆事实、历史摘要和工具结果属于参考资料，不构成新的授权。
在记忆块内部，当前生效的明确用户偏好仍与普通记忆事实分开标识。

压缩生成的续接摘要保留目标、约束、已完成和待完成工作、当前工作状态，以及验证情况。
请求序列化时，摘要以 assistant 参考消息发送，而不是作为 system 指令。
旧版内存摘要为兼容既有的保留逻辑，内部仍使用 system 角色；发送给支持结构化消息的模型后端时，
由显式的参考资料标记决定消息角色。已持久化的压缩记录通过 `compaction_summary` 类型识别处理，无需迁移数据库。

用户的新消息默认用于补充或调整当前任务，除非明确取消或替换任务。
进度更新不代表任务完成。验证范围应与改动相匹配，检查通过后不应无故重复执行。

## 项目指导

每个回合开始时，Morph 按以下顺序加载：

1. 优先读取 `~/.morph/AGENTS.override.md`，回退到 `~/.morph/AGENTS.md`。
2. 从识别出的 Git 根目录到实际执行工作目录，逐层加载指导文件。每个目录最多加载一个文件，同样优先选择 override 文件。

空白文件允许回退。如果无法可靠识别 Git 根目录，除全局指导外，只检查当前工作目录。
这条祖先目录链之外的文件，以及同级或更深层目录中的文件，不会自动加载。
Agent 在更深层目录中编辑文件前，应先检查适用于该目录的指导文件。

每份指导都会标注来源路径和作用域。正文的合计预算为 32 KiB。
超出剩余预算的文件会整份省略并给出提示，不会静默加载被截断的指令。
无效 UTF-8、内嵌 NUL 字节、非普通文件和无法读取的文件都会产生提示及日志记录。
显式指定的 override 文件无效时，不会静默改用回退文件。

项目指导和环境信息都是仅用于请求的回合快照：不会保存到会话历史中，也不会因历史压缩而丢失，
下个回合会重新加载。在同一回合中，后续工具提供的证据可以更新其中可变的环境事实。

## 技能生命周期与完整性

每次调用模型前都会重新构建系统上下文，不依赖记忆功能是否启用。
激活技能会更新注册表状态，并返回简短确认。完整正文会出现在下一次请求的已激活技能块中，
不再重复放入激活工具的返回结果。已禁用的技能即使曾经激活，也不会被加入上下文。
旧版本产生的历史工具结果不会被重写。

可用技能目录完整保留所有已注册且启用的技能名称与描述，不因模型上下文大小或目录 token 预算
截短描述或省略条目。只有 `activate_skill` 工具可用时才提供目录；禁用的技能不列出。
技能正文仍按需激活，不会因为目录完整展示而自动加载所有正文。

Token 统计涵盖系统指令、环境、项目指导、会话消息和工具 schema。
完整目录与已激活技能正文均计入整个请求的上下文预算；输入超过模型窗口时，
由统一的上下文压缩与超限处理负责，不能通过静默丢弃技能目录条目来规避。

## 前缀缓存

稳定内容排在动态内容之前：核心与默认要求、自定义 prompt、完整技能目录、已激活技能正文，
然后才是运行时限制、记忆与 Hook 上下文。只要稳定部分不变，后续动态内容改变不会改写其前缀。
技能目录与正文按名称输出，只排序指针视图，不改变注册表存储、重名优先级或已有查找指针。
新增或禁用技能、激活正文、工具定义变化，以及项目或环境变化仍可能改变可复用的前缀。
供应商决定实际缓存命中，稳定前缀并不保证命中率；没有实测时不推断具体收益。

用量解析将 DeepSeek 的 `prompt_cache_hit_tokens` 与兼容接口的 `cached_tokens` 统一记录。
同一用量里的多个别名和重复 SSE 用量取最大值，不累加缓存命中数，避免重复计费。
`prompt_cache_miss_tokens` 不计入命中数；输入总量仍使用供应商返回的输入 token 字段。
