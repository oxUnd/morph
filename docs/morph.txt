Morph Manual						*morph*

Morph is a terminal-native multimodal AI agent.  It can chat, read files,
generate or inspect images, generate video, call local tools, load skills, and
connect to MCP servers.

Use this manual when answering questions about how to use or configure Morph.
Read the relevant tag section first, then answer with concrete commands or
config snippets.

QUICKSTART						*morph-quickstart*

Build from source:

	cmake -S . -B build
	cmake --build build

Create the default config:

	mkdir -p ~/.morph
	cp config.toml.example ~/.morph/config.toml

Set the API key required by the configured provider:

	export OPENAI_API_KEY=sk-...

Run Morph:

	./build/morph

Useful flags:

	-c <path>	Use another config file.
	-s <name>	Start or switch to a named session.

Inside Morph, type /help to list commands and /quit to exit.

CONFIGURATION						*morph-config*

The default config path is:

	~/.morph/config.toml

Create it from:

	config.toml.example

Important sections:

	[general]	Output directory, log path, default session.
	[model.text]	Chat model used by the ReAct loop.
	[model.vision]	Optional image understanding and OCR model.
	[model.image]	Image generation/editing model.
	[model.video]	Video generation model.
	[credits]	Credit tracking and per-model prices.
	[exec]		Shell, timeouts, output limits, and network for exec.
	[react]		Tool loop, guardrails, HITL, and tool policy.
	[react.permissions]	Permission profile selection.
	[context]	Context compression settings.
	[memory]	Persistent memory settings.
	[sync]		Optional backup of the ~/.morph directory.
	[render]	Terminal image protocol and video player arguments.
	[ext]		Extension directory and sandbox resource defaults.
	[dynamic_tools]	JavaScript tool execution profiles.
	[prompt]	Extra system prompt file or prompt directory.
	[skill]		Custom skill directory.
	[[mcp.servers]]	MCP server definitions.

API keys should normally be referenced through api_key_env, not written
directly into the config:

	api_key_env = "OPENAI_API_KEY"

Then set the environment variable before launch.

MODELS							*morph-models*

Morph uses separate configuration roles for each model workload:

	[model.text]	Chat, planning, tool selection, and text answers.
	[model.vision]	Optional image understanding, OCR, and img_qa.
	[model.image]	img_gen, img_inpaint, img_compose.
	[model.video]	vid_gen.

OpenAI-compatible text example:

	[model.text]
	provider = "openai"
	model = "gpt-4o"
	api_base = "https://api.openai.com/v1"
	api_key_env = "OPENAI_API_KEY"
	context_limit = 128000
	max_tokens = 4096
	timeout_seconds = 300
	retry_count = 3

Provider-specific text request fields can be merged with extra_body_json.
Morph still owns model, messages, tools, stream, stream_options, and
max_tokens, so extra_body_json cannot replace those fields:

	[model.text]
	provider = "openai"
	model = "gpt-4o"
	api_base = "https://api.openai.com/v1"
	api_key_env = "OPENAI_API_KEY"
	extra_body_json = '''
	{
	  "reasoning_effort": "high",
	  "chat_template_kwargs": {"enable_thinking": true}
	}
	'''

DeepSeek example:

	[model.text]
	provider = "deepseek"
	adapter = "deepseek"
	model = "deepseek-v4-flash"
	api_base = "https://api.deepseek.com"
	api_key_env = "DEEPSEEK_API_KEY"
	context_limit = 128000
	max_tokens = 32768
	timeout_seconds = 300
	retry_count = 3

The DeepSeek adapter preserves reasoning_content across tool calls and omits
tool_choice while thinking is active.  DeepSeek V4 enables thinking by
default, so no extra_body_json is required.  The adapter is inferred when
provider = "deepseek", but setting adapter = "deepseek" explicitly makes the
wire protocol clear.

To disable thinking explicitly, add:

	extra_body_json = '''
	{"thinking":{"type":"disabled"}}
	'''

Volcengine Ark example:

	[model.text]
	provider = "volcengine"
	model = "ep-xxxxxxxx"
	api_base = "https://ark.cn-beijing.volces.com/api/v3"
	api_key_env = "VOLCENGINE_API_KEY"

Optional vision model example:

	[model.vision]
	provider = "openai"
	model = "gpt-4o"
	api_base = "https://api.openai.com/v1"
	api_key_env = "OPENAI_API_KEY"
	max_tokens = 4096
	timeout_seconds = 300
	retry_count = 3

Leave [model.vision] absent or set model = "" to keep img_qa unavailable.
DeepSeek's vision-capable deepseek-flash model uses adapter = "deepseek".  Set
extra_body_json = '''{"thinking":{"type":"disabled"}}''' when thinking must
remain disabled.

OpenAI image example:

	[model.image]
	provider = "openai"
	model = "gpt-image-2"
	api_base = "https://api.openai.com/v1"
	api_key_env = "OPENAI_API_KEY"

Volcengine Seedream example:

	[model.image]
	provider = "volcengine"
	model = "doubao-seedream-5-0-260128"
	api_base = "https://ark.cn-beijing.volces.com/api/v3"
	api_key_env = "VOLCENGINE_API_KEY"

Image models use a protocol adapter because generation, editing, output
encoding, and size rules differ by provider. Morph infers openai-images from
provider = "openai" and volcengine-images from provider = "volcengine". For a
custom provider name, select one explicitly:

	adapter = "openai-images"

Supported image adapters are openai-images and volcengine-images. GPT Image
and Volcengine adapters support ordered reference_images. Pass every reference
in one img_gen call; the adapter validates editing and multi-reference support
for the configured model.

Volcengine Seedance 2.0 video example:

	[model.video]
	provider = "volcengine"
	# Optional; inferred from provider when omitted.
	# adapter = "volcengine-videos"
	model = "doubao-seedance-2-0-260128"
	api_base = "https://ark.cn-beijing.volces.com/api/v3"
	api_key_env = "VOLCENGINE_API_KEY"
	poll_interval_seconds = 5
	poll_timeout_seconds = 600

Use the faster Seedance variant by changing only model:

	model = "doubao-seedance-2-0-fast-260128"

The configured video model determines available inputs:

	Seedance 1.0	Text and one first-frame reference image.
	Seedance 1.5	The above plus generated audio.
	Seedance 2.0+	Multiple images, reference videos, reference audio,
			and generated audio.

Unknown model IDs, including opaque ep-... endpoint IDs, are treated
conservatively: text and one image are allowed, while multi-image, video, and
audio references are rejected before sending a request. An empty model value
is not replaced by a hidden fallback and reports "not configured".

vid_gen accepts ordered reference_images, reference_videos, and
reference_audios arrays. Reference audio supports local MP3/WAV files or
HTTP(S) URLs, requires at least one image or video reference, and enables
generate_audio. Models that support audio generation default to
generate_audio = true; callers can explicitly disable it when no reference
audio is supplied.

If image or video generation fails with "not configured", check the matching
[model.image] or [model.video] section and its API key environment variable.

CLI COMMANDS						*morph-cli*

Common interactive commands:

	/help [command]	List commands or show one command.
	/quit		Exit.
	/new [name]	Create a new session.
	/list [n|query|--all]	List sessions.
	/switch <name|id|^N>	Switch session.
	/rename <name>	Rename current session.
	/delete <name|id>	Delete a session.
	/history [n|--all]	Show, diagnose, repair, or export history.
	/model [name]	Show or change the text model for the session.
	/config		Print loaded configuration.
	/trace [--from-db]	Show the latest ReAct trace.
	/context	Show token context usage.
	/compress	Compress old conversation context.
	/credits	Show estimated credit usage.
	/save [format]	Export the session to a file.
	/clear		Clear the terminal screen.
	/memory [show|history|explain|set|unset|clear|jobs]
	/permissions [list|revoke <id|program>|clear ...]
	/tasks [list|show|add|every|update|cancel|run]
	/inbox [list [limit]|read <id>]
	/sync [status|now|conflicts|restore <trash-id>|restore-db ...]
	/skill list	List skills.
	/skill info <name>
	/skill activate <name>
	/mcp list	List MCP servers.
	/mcp connect <name>
	/mcp tools <name>
	/ext list	List extension tools.
	/image <path>	Inject an image into context.
	/render <path>	Render an image, video, or markdown file.

Most commands have short aliases: /q, /h, /n, /ls, /s, /rn, /del, /m,
/cfg, /t, /ctx, /cp, /r, /mem, /perms, /x.  Use /help /command for exact
usage.

TOOLS AND PERMISSIONS					*morph-tools*

Built-in read-only tools include:

	file_read	File preview.
	file_list	Directory listing.
	file_info	File metadata.
	img_info	Image metadata.
	credits		Credit usage.
	memory		Memory inspection.
	activate_skill	Load a skill's instructions into context.
	plan		Create and manage a multi-step plan.
	agent_status	Check an asynchronous sub-agent.

Creative and processing tools include:

	img_qa		Answer questions about an image.
	img_gen		Create or transform images.
	img_annotate	Ask the user to mark an image.
	img_inpaint	Edit labeled bounding boxes.
	img_compose	Blend labeled objects between images.
	img_resize	Resize images.
	img_convert	Convert image formats.
	vid_gen		Generate video.

Workspace, task, and configuration tools include:

	apply_patch	Patch text files inside the active work directory.
	config_edit	Safely patch the active Morph configuration.
	memory_preference	Persist an explicit user preference.
	tasks		Create and manage scheduled tasks and the inbox.
	tool_create	Create or update a dynamic JavaScript tool.
	delegate	Start a sub-agent asynchronously.
	fanout		Run several sub-agent tasks in parallel.
	ask_user		Ask the user a question and wait for an answer.

Shell and process tools include:

	exec		Run a shell command with workdir, timeout, and sessions.
	process		Poll, write to, interrupt, or kill an exec session.
	request_permissions  Ask for the smallest additional filesystem access.

The exec tool runs shell commands; the process tool manages the resulting
process sessions.  Both are registered always and share one configuration
table:

	[exec]
	shell = "/bin/bash"
	default_timeout_ms = 120000
	yield_time_ms = 10000
	max_inline_output = 32768
	max_session_output = 1048576
	kill_grace_ms = 500
	network = false

Each command is parsed before execution.  Morph derives the programs it would
run, then asks for approval scoped to those programs.  If a command cannot be
parsed safely, exec returns approval_required instead of running it.  A single
approval can apply to this call only, to the whole session, or permanently.
Persistent grants are stored per project and listed with /permissions.

The sandbox grants read access to system toolchain paths (/usr, /bin, /sbin,
/System, /Library, /opt/homebrew, /private) and read, write, and delete
access to /tmp.  The command workdir also gets read, write, and delete
rights.  Additional write or delete paths may be requested through approval
and are never persisted unless you choose the permanent option.  Proxy
variables (lowercase and uppercase) plus SSL_CERT_FILE,
SSL_CERT_DIR, and CURL_CA_BUNDLE are inherited automatically; other
non-essential variables are still filtered.

Commands that outlive yield_time_ms return a session_id.  Continue them with
the process tool, whose action is one of poll, write, interrupt, or kill.

Long-term trusted directories belong in a permission profile, which adds
trusted roots at startup and never weakens the OS sandbox:

	[react.permissions]
	active_profile = "developer"
	request_tool_enabled = true

	[[react.permission_profiles]]
	name = "developer"
	workspace_roots = []
	write_paths = []
	delete_paths = []

PTY allocation, platform-scoped process inspection, and POSIX IPC are
available to normal developer commands without granting access to arbitrary
devices.  Networking stays off unless [exec].network is enabled.
On Linux, process visibility follows the host /proc DAC because Morph does not
create a PID namespace.
See docs/sandbox.md for the extension capability names, platform policy, and
macOS nested-sandbox testing caveat.

Human-in-the-loop approval:

	[react]
	hitl_enabled = true
	hitl_tools = ["img_gen", "vid_gen"]
	hitl_auto_approve_readonly = true

When HITL is enabled, Morph asks before selected tool calls.

SCHEDULED TASKS					*morph-tasks*

A task is a prompt Morph runs later, either once or on an interval.  When a
task is due, the agent executes the prompt and delivers the final answer as a
notification.  Results go to a persistent inbox.

Commands:

	/tasks list [status]	List tasks.
	/tasks show <id>	Show one task in detail.
	/tasks add <unix_time|+seconds> <prompt>
	/tasks every <seconds> <prompt>
	/tasks update <id> <unix_time|+seconds> <prompt>
	/tasks cancel <id>
	/tasks run [limit]	Process due tasks now.
	/inbox list [limit]	List notifications.
	/inbox read <id>	Mark a notification as read.

Examples:

	/tasks add +300 Summarize today's AI news in five points.
	/tasks every 3600 Summarize the most important AI news.

Times are UTC Unix seconds, or a relative +seconds value.  The agent can also
create and manage tasks through the tasks tool, which supports the ops create,
update, list, cancel, inbox, and mark_read.  Due processing stays in the
scheduler; run_due is not available to the agent.

The interactive CLI runs a lightweight background scheduler that checks due
tasks about once per second.  Tasks and notifications live in the Morph
SQLite database, so they survive after a session ends.

DYNAMIC TOOLS						*morph-dynamic*

Morph can write small JavaScript tools at runtime and call them immediately.
Tools run in an embedded QuickJS interpreter, not Node.js.  They may use the
host APIs listed below and return a JSON-serializable value.

Tools:

	tool_create	Create or update a dynamic tool.
	tool_promote	Move a session tool into the persistent tool directory.
	tool_delete	Delete a dynamic tool.
	tool_history	List checkpoints for a tool.
	tool_diff	Show a diff against a checkpoint.
	tool_rollback	Rewind a tool to a checkpoint.

A dynamic tool defines a global run(args) function, or async run(args).  Every
successful create or update records a checkpoint.

Available host APIs include morph.fs (readText, writeText), morph.env.get,
morph.tool.call, morph.exec, morph.fetch, morph.image (metadata, resize, crop,
extend, rotate, convert, compose, frame, open), morph.canvas (create,
loadImage, toFile, toBuffer), and WebAssembly.

Capabilities are controlled by the active profile under [dynamic_tools], not
by the tool itself:

	[dynamic_tools.local]
	default_capabilities = ["fs_read", "fs_write", "network", "process",
	                        "env", "mcp", "model", "shell", "image", "wasm"]

The server profile starts from an empty capability list.  Set
dynamic_tools.mode to "server" to use it; FastCGI and other non-interactive
front-ends default to server mode when mode is not set explicitly.

See docs/quickjs-tools.md for the full API surface and sandbox details.

SKILLS							*morph-skills*

Skills are instruction packs with a SKILL.md file.  They teach Morph a
specialized workflow.

Default discovery paths:

	~/.morph/skills/
	~/.agents/skills/

Custom path:

	[skill]
	dir = "/path/to/skills"

Commands:

	/skill list
	/skill info <name>
	/skill activate <name>
	/skill deactivate <name>

Skills follow the Agent Skills open standard.  Short alias: /sk.

If a task matches a skill, Morph can activate it automatically through the
activate_skill tool.  Activation loads the full SKILL.md instructions into the
current context.

MCP							*morph-mcp*

Morph can connect to Model Context Protocol servers by stdio or HTTP.

Stdio filesystem example:

	[[mcp.servers]]
	name = "filesystem"
	transport = "stdio"
	command = "npx"
	args = ["-y", "@modelcontextprotocol/server-filesystem", "/path"]
	auto_connect = true
	connect_timeout = 30

HTTP example:

	[[mcp.servers]]
	name = "remote-api"
	transport = "http"
	url = "https://api.example.com/mcp"
	auth_token_env = "MCP_REMOTE_TOKEN"

Commands:

	/mcp list
	/mcp connect <server>
	/mcp disconnect <server>
	/mcp tools <server>
	/mcp resources <server>
	/mcp prompts <server>

If tools do not appear, confirm the server starts, auth env vars are set, and
connect_timeout is long enough for the server.

EXTENSIONS						*morph-exts*

Extensions are local tool packages under:

	~/.morph/exts

or the directory configured by:

	[ext]
	dir = "~/.morph/exts"

Install from GitHub:

	/ext install github:owner/repo
	/ext install github:owner/repo@v1.2.0
	/ext install github:owner/repo//exts/foo

List installed extension tools:

	/ext list
	/ext info <name>

Extensions declare their entrypoint and permissions in manifest.toml.

MEMORY, CONTEXT, CREDITS				*morph-memory*

Memory can store user facts, procedures, and episode summaries:

	[memory]
	enabled = true
	max_facts = 6
	max_context_chars = 3000

Inspect or change it:

	/memory show
	/memory history
	/memory explain
	/memory set <key> <value> [personal|project|session]
	/memory unset <key> [personal|project|session]
	/memory jobs
	/memory clear [all|facts|episodes|procedures]

Explicit preferences are stored by scope.  Session overrides project, which
overrides personal.  Use /memory explain to see which value is effective.

Context compression protects long sessions:

	[context]
	summarize_threshold_ratio = 0.8
	compress_target_ratio = 0.5
	keep_recent_rounds = 6

Inspect current usage:

	/context

Manually compress:

	/compress

Credits track estimated usage and optional warning limits:

	/credits

CONFIG EDITS						*morph-config-edit*

Morph can safely edit its active config when the user explicitly asks and
approves. The config_edit tool prefers a minimal Codex-style patch targeting
only config.toml. It preserves comments and formatting, validates the result,
creates config.toml.bak, detects concurrent changes, and atomically replaces
the config.

Safe workflow:

	1. Read the current config or config.toml.example.
	2. Explain the exact change.
	3. Ask for user approval.
	4. Patch only the active Morph config file.
	5. Validate the complete resulting configuration.
	6. Back up and atomically replace the file.
	7. Tell the user to restart Morph.

Configuration is not hot-reloaded. config_edit completes the current tool
turn and returns restart_required = true; it does not terminate Morph.

Do not put API key values into config unless the user explicitly provides
that secret and insists. Prefer api_key_env and tell the user to export the
environment variable.

TROUBLESHOOTING					*morph-troubleshooting*

"no API key configured"

	Check api_key_env in the matching model section and export that env var
	before starting Morph.

"no image model configured"

	Check [model.image], provider, model, api_base, and api_key_env.

"no multimodal LLM configured"

	img_qa uses [model.vision]. Configure a vision-capable model there.

"video adapter does not support reference videos/audios"

	Check [model.video]. Reference video and reference audio require a
	recognized Seedance 2.0+ model ID. Opaque ep-... IDs use conservative
	capabilities.

"exec cannot run a command"

	Check the returned error.code:

	approval_required	The command could not be parsed safely, or it was
				not approved.  Rewrite it without dynamic
				construction, or approve it when prompted.
	approval_unavailable	This run has no interactive approval channel.
	permission_denied	You denied the command.
	spawn_failed / invalid_workdir	The process could not start, or the
				workdir is invalid.

	A command that needs a directory outside the sandbox should be added to a
	permission profile.  See the TOOLS AND PERMISSIONS section.

"skill not found"

	Check /skill list.  Confirm the skill has SKILL.md and a description in
	frontmatter.  Confirm [skill].dir if using a custom directory.

"MCP server has no tools"

	Run /mcp connect <name>, then /mcp tools <name>.  Check command, args,
	env, auth_token_env, and connect_timeout.

"config changes did not take effect"

	Restart Morph.  Most config values are loaded at startup.
